# v0.2.0 — Public CPU replay and evidence navigation

This release makes the research software easier to inspect and run. It adds no
new research performance result.

- A documented, local CPU path generates markets, fits mature history, selects
  parameters, settles delayed conversion reports and resumes frozen work.
- Expected software output: 90 validation records, 45 confirmation records,
  one independent confirmation market, mature final settlement and hard budgets
  respected. `business_target_pass` remains `false`.
- CI checks lint, formatting, tests and both CPU smoke paths on Python 3.11/3.12.
  Pytest runs the actual delayed-feedback CLI and frozen resume; the existing
  workflow also runs the earlier offline-policy smoke command. Release
  publication follows a successful CPU workflow on the same main commit.
- The attached source manifest records SHA-256 identities, reference package
  versions and observed CPU replay output. GitHub source archives include the
  public reports; private model/data artifacts are excluded.
- The report index now links conditional Flow Matching, delayed-feedback
  confirmation, twelve pending-use strategies and the research decision journal.

Start with [the replay guide](https://github.com/KAMCHIU-LAB/trajectory-lab/blob/v0.2.0/docs/reproduce.md).

## Research boundaries

The earlier +17.6% score result is confined to a declared overestimation scenario
in a custom fixed-opponent simulator. Flow's additional decision value remains
unconfirmed. Delayed-feedback correction produced +1.21% in its independent
study, below its +3% practical target, with a long-delay overestimation failure.
The small software replay cannot establish or reproduce these historical gains.

Historical reports retain their original source identities. A byte-formatting
change in this release is not a rerun of a historical experiment. See the tagged
findings, provenance document and research journal for full comparisons and
limitations.
