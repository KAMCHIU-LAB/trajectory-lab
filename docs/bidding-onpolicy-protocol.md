# 冻结策略在验证轨迹上的预测审计（post-hoc）

## 观察时点与问题

本协议在查看 main-v2 与 control-v1 结果后制定，属于 post-hoc 描述性诊断。
已知 control 验证集选中策略的平均 score 为 6.3916，原始 response 为 15.3847；
选中控制器的 CPA 违约频率为 95.93%。这些结果触发本次审计，不能把本协议称为
看到结果前的预注册，也不能用本次结果确认唯一的因果瓶颈。

本次检查两种冻结策略各自实际访问的状态与所选动作上的预测误差、动作分布和预算节奏。
策略会改变后续状态，两个方法访问的状态和选择的动作可能不同；误差差异同时受预测器、
动作选择、场景和状态分布影响，不是固定状态下的单因素因果比较。

## 冻结范围与信息边界

- 只使用 main-v2 已声明的 6 个验证市场、6 个 focal 广告主、3 个 response 种子
  （11、23、37）和 5 个压力场景。两个方法共 1,080 个完整周期、51,840 个时段。
- 对照是 control 验证报告中的 `response`，即原始、未加在线预测修正的软决策策略。
  实现复用 `Learned`，沿用相同检查点、24 步上下文和原始归一化。
- 另一方法完全复用 control selection 中的 candidate、已选 rate 与 calibration mode。
  `budget-only` 按原实现使用零质量价格更新率及 `none` 校准模式。不得重选参数。
- 模型在 CPU、2 个 Torch 线程上以 eval 模式运行。无拟合、无新训练、无参数搜索，
  不读取测试市场、独立确认市场或其结果。只读取原 control 验证结果作为重放核对依据。
- 不修改 main/control 源码、配置、检查点或任何已有实验结果。

## 每时段审计与预算删失

策略按原接口接收 causal state、此前动作/奖励、预算和 CPA，并返回动作与已有 diagnostic。
执行器按原实现结算；策略的 `observe` 只接收实际结算反馈与原 diagnostic。
审计包装器随后读取 evaluator-private Tape 中该时段 `action * scenario_bias` 对应的
未截断成本/转化曲线标签。该标签不写入 diagnostic，不传给策略，也不改变任何策略状态。

包装器通过只读 forward hook 捕获策略本次实际前向的完整四条曲线；hook 返回 None，
不改变模型输出，不额外执行模型前向。原 response 使用 remaining 两条曲线选动作，
paced 使用 current 两条曲线及已冻结校准/资源价格选动作，因此分别报告这两类误差。
审计预测是原始模型曲线；paced 的在线校准仍只存在于原策略内部，不把审计标签用于校准。

记录所选动作的 diagnostic 当前成本/转化预测，并核对其与捕获的 current 曲线相同。
当前真实标签是匹配有效动作在当前 tick 的未截断响应。remaining 真实标签定义为
从当前 tick 到 47 **恒定同一当前有效动作** 的未截断成本/转化和，包含当前 tick。
它不是策略随后换动作的实际回报，也不使用剩余预算截断。
在 `mid_over_50` 中同样固定当前 `action * 当前 bias`，不沿未来 bias 路径改变动作；
因此这个审计标签不能解释为预测了未来偏差切换或实际后续轨迹。
预算截断时段仍纳入预测误差：其真实标签来自私有未截断曲线，不能把实际删失结算量当标签。
本次允许 evaluator 审计全部时段，不意味着部署时能够得到这些反事实标签。

## 固定指标与聚合

1. 成本除以周期预算，转化乘以目标 CPA 再除以周期预算。current 两组乘 48、
   remaining 两组乘 1 后取 `log1p`，沿用四曲线训练尺度 `[48,48,1,1]`。
   报告 chosen-action logMSE、beta=1 smooth L1 和有符号平均 log 误差；
   current 与 remaining 分开报告，各自的成本/转化两组及时段等权。
   smooth L1 在误差绝对值小于 1 时为 `0.5 * error²`，否则为 `abs(error) - 0.5`。
2. 分成本/转化报告归一化预测总量 / 归一化未截断真实总量。
   分母为零时报告 null，不人为填充比例。
3. 报告 11 个名义动作的计数和频率、前 12 个时段各自结算后的累计预算利用率，
   以及预算截断时段数和频率。早期预算指标使用实际结算支出，不使用未截断标签。
4. 报告每方法的 pooled、按场景、按种子、按市场，以及场景×方法×种子×市场聚合。
   每周期均为 48 个时段，周期均值与时段均值在相应口径内等权；另保留各组样本数。
   聚合最终 score、转化、成本、CPA 违约率用于描述访问轨迹，不作为新的晋级标准。

## 重放一致性门槛

对每个 market/focal/scenario/method/seed，核对原 control 验证 JSON 的对应记录：
转化和 violation 必须精确一致；成本与 score 使用固定 `rtol=1e-9, atol=1e-8`。
任一周期不匹配即中止并记录失败，不调整容差、不替换策略、不删除不匹配周期。
完整且唯一的预期覆盖为每方法 540 个周期。另核对包装器与原 rollout 的预算截断计数。

## 输出与解释边界

默认输出为 `artifacts/bidding/onpolicy-v1` 下的 `manifest.json`、`summary.json`、
`status.json`，只含文本与聚合统计；不保存 state、流量、逐时段标签或模型权重。
manifest 绑定本协议、自身实现、依赖实现、主实验来源身份、control 来源/selection/
验证结果以及模型检查点哈希。独占锁、原子写入、完成结果哈希校验保护重复运行；
不同身份不得复用同一输出目录。

市场数只有 6，同市场/广告主/种子的时段和周期相关。报告不提供把 51,840 时段视作
独立样本的置信区间，不筛选有利场景，不声称独立确认或策略改进。
预测误差、动作分布与早期预算支出只能描述与负结果一致的现象；任何控制器改进及因果
解释均需新的冻结方案和未用于本次诊断的数据。本次不会据结果改写既有两轮研究结论。
