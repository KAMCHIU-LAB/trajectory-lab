# 实验记录与追加规则

研究记录用于回答：发现了什么问题，为什么选择这个方案，什么证据改变了决定。新研究从本模板复制到独立文件，填写真实运行身份和证据位置，并在[演进记录](bidding-research-journal.md)添加入口。

## 记录状态

使用明确状态：拟议未执行、已冻结待运行、开发完成未晋级、开发通过待确认、独立确认完成、有效中断、完整性失败。计算完整性、科学假设判定、业务投入门槛分别记录。

旧研究的回溯补录写明整理日期与原证据，假设冻结时点无法核实时注明。新研究运行前固定问题、对照、门槛和停止预算；后续修订追加版本与变更理由。

## 运行前填写

- **问题与触发证据：**引用现有异常、日志或统计，解释它影响哪个决策。哪些事实已经知道？哪些仍需检验？
- **可证伪假设：**写成“在条件 C 下，方案 A 相对 B 达到门槛 G”；说明结果怎样会推翻它。
- **方案依据与备选：**写出机制依据，列出强简单方案、复杂方案和不继续的选择；说明本轮取舍。
- **信息与标签契约：**策略在何时能看到什么；预测目标是什么；终局如何结算；模拟器真值如何隔离。
- **比较与公平性：**训练数据、输入、骨干、拟合预算、调参预算、动作与执行器哪些共享，哪些不同。
- **数据与样本单位：**训练 / 开发 / 确认范围及历史使用记录；独立单位、配对键和相关重复。
- **成功与保护门：**主比较、效应门槛、区间方法、转化保留、风险限制、子组和多重比较口径。
- **停止与资源：**最大候选数、训练预算、预计时间与设备；何时停止，何时允许打开新确认集。
- **复现身份：**源码提交、配置与数据 / 历史哈希、随机种子、输出目录标识、恢复身份要求。公共版本仅写可发布位置。
- **冻结证据：**冻结日期、协议版本 / 哈希及保存位置；区分仓库内部冻结与外部注册。

## 运行后追加

- **执行事实：**真正运行的候选、种子和市场；缺失项、中断、异常、恢复和参数偏离。计划与实际分开。
- **结果与完整性：**原始标量表、聚合脚本 / 版本、区间和所有门槛；缺测不能写成零效应。
- **反例与代价：**最差场景、转化损失、风险变化、计算成本；与强参考和弱参考的差异同时报告。
- **解释层级：**逐条标注观测事实、事后解释、结构推导、未验证假设。写出替代解释与尚不能归因之处。
- **决定与理由：**晋级、停止、保留开发候选或另立研究；引用触发决定的门槛与数值。
- **能力与贡献：**写出完成的技术动作、得到的可检验认识及其如何改变方案；个人分工、公开方法与 AI 辅助按实际记录。
- **对外表述：**一句可支持的结论，紧邻比较对象、样本范围与重要代价；列出仍待确认的命题。
- **下一步：**只写最有信息量的下一项检验、需要的新数据与停止条件；未执行方案保持拟议状态。

## 追加纪律

运行后保留原候选和阈值；假设变化另开版本。确认集用于检验冻结方案，新的选择需要新的数据边界。共享数据的诊断与开发结果不能计为独立重复确认。

发布前核对数字、链接、来源与隐私；公共记录只包含公开代码、允许发布的标量和身份。保密环境的日志、数据、截图、本机路径与凭据留在发布范围外。记录核对日期与范围，避免把一次扫描写成无边界保证。
