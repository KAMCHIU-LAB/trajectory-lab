# Experimental protocol

## Question and scope

How do high-return filtering and return-stratified sampling affect cloning,
implicit value learning, and return-conditioned sequence modeling under a fixed
small compute budget? Do return differences coincide with changes in the data
support visited by the learned policy?

The contribution is an inspectable experimental protocol and diagnostic toolchain.
BC, IQL, and DT are public methods. Their implementation here is independent and
compact; neither the algorithms nor their names are claimed as new research.

## Two evidence levels

1. **Controlled study:** Pendulum-v1 trajectories generated by a documented mixture
   of energy shaping, noisy control, and random actions. This task is deliberately
   lightweight and cannot establish industrial or general RL performance.
2. **External check:** a seeded uniform episode subset of Minari
   `D4RL/pointmaze/umaze-v2`. The recovered evaluation environment is used.
   This checks transfer of the implementation and protocol, not reproduction of
   published full-dataset scores. The full dataset is not redistributed.

The smoke configuration belongs to neither level: 100 updates and one training
seed are integration evidence only.

## Data isolation

- Content-identical episodes are grouped before the 80/10/10 source split.
- The training pool alone supplies data views and normalization statistics.
- Validation trajectories calibrate a descriptive support-distance reference.
- Held-out source trajectories remain unused by optimization; final policy quality
  is evaluated by fresh simulator interactions with a separate fixed seed list.
- An episode has T actions and T+1 observations. The dataset validator rejects
  internal terminal/timeout flags, malformed arrays and non-finite values.
- A real terminal state removes the Bellman bootstrap. A time-limit truncation
  keeps it. DT sequences end at each stored episode boundary, including timeouts.

## Data views

- `uniform`: shuffle training episodes without using their return.
- `top_return`: greedily select episodes in descending undiscounted total return.
- `return_stratified`: partition episodes into four return-rank groups, shuffle
  within each group, and interleave candidates from the groups.

All views use a common transition cap and complete episodes; episodes that do not
fit the remaining budget are skipped. A declared budget tolerance is enforced and
actual counts are reported. Pendulum episodes have equal length and achieve an
exact shared budget. Views can overlap; they are not independent datasets.

High return is not equivalent to coverage or task quality. With variable-length
episodes, total-return selection can also select episode length. The controlled
comparison uses fixed-length Pendulum episodes. PointMaze currently uses only the
uniform view; extending that comparison requires an explicit length analysis.

## Training and evaluation

- CPU / one thread is the local reference configuration. Optional accelerator
  selection does not imply its performance or determinism has been validated.
- BC and IQL share the same bounded-mean Gaussian actor and likelihood objective;
  IQL adds expectile value learning, twin Q learning, and advantage weights.
- DT interleaves return, state, action tokens. Action t is predicted from state
  token t, before action token t. A unit test perturbs current/future labels to
  check the causal boundary. This small baseline uses a pre-norm causal backbone,
  no dropout, and the stated configuration rather than the original paper tuning.
- DT target return is the declared quantile of training-view episode returns.
  IQL reward scale and DT return scale are explicit and do not change evaluation
  rewards.
- All algorithms receive the declared number of gradient updates and batch size.
  DT consumes context windows and more token computation; equal updates are not
  equal FLOPs. Wall time is reported, and the comparison is not compute-optimal.
- Final evaluation uses the final checkpoint. Validation curves are diagnostic;
  test episodes never select a checkpoint or target return.
- The same environment seed list is used across models. Across-seed standard
  deviation is calculated from independent training-run means, not pooled episode
  returns. Three seeds are limited evidence, not a significance guarantee.
- Random/controller references are labeled non-learned references; the controller
  is not an oracle. Only raw return and native task success are reported.

## Support diagnostic

A common normalizer is fitted on the source training pool. Each view provides up
to 5,000 reference states. Euclidean nearest-neighbor distances are calculated for
validation and final policy states. The fraction above the validation 95th
percentile is descriptive; it is not a calibrated OOD score or a safety certificate.
PCA also uses training data only. Low-dimensional plots can hide missing support,
and duplicate/highly correlated states affect nearest-neighbor distances.

## Reproducibility and result integrity

Source arrays, views, configuration, implementation files, relevant package
versions, and seeds identify an experiment. Complete results can be skipped on a
repeat invocation; interrupted runs restore learner, optimizer and RNG state from
an atomic checkpoint. Exact resume is verified on the CPU learner path. Accelerator
and cross-version bitwise equivalence are not promised.

A report enumerates the manifest's expected runs. It rejects incomplete suites,
duplicate identities, changed evaluation seeds, and inconsistent return summaries.
The exported evidence includes per-run returns and histories, source IDs, budgets,
versions and digests. Checkpoints and upstream datasets stay in ignored artifacts.

The optional CPU recovery driver schedules independent training runs in spawned
processes using the same learning function, settings, and run IDs. It requires the
serial runner to be stopped, checks source/code/runtime identity, and records its
own source digest and worker count. A subprocess integration test checks recovery
of a missing result from a durable checkpoint. Parallel runs share the host, so
recorded wall times must not be interpreted as isolated speed measurements.

## Ablation

`configs/iql-ablation.toml` sets the actor advantage temperature to zero while
retaining the IQL code path. Because BC and IQL share their actor and sampler,
their actor updates then match under matching seeds/settings. This invariant is
tested. The experiment separates actor weighting from merely adding critic code.

## Limitations and follow-up

One controlled task plus a small public subset is not a general algorithm ranking.
No systematic hyperparameter search, full D4RL suite, deployment evaluation, or
industrial revenue/CPA result is claimed. Descriptive support differences do not
prove the cause of return differences. Future studies should add tasks, stronger
baselines, additional training seeds, compute-matched comparisons, and independently
held-out environment variations before broadening the conclusions.
